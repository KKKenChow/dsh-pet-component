## 第四轮：命令面优先级 + 精简 props + 合并 demo

### 修改（行为修正）

- **命令面不再被 `motion` prop 顶掉**：`usePetMotion` 的层次改为
  `dragging 手势态 > 命令面 pet.motion(...) > motion prop > idle`。
  命令面下发过的动作持续生效，直到 `motion` 取值变化 —— 那时命令层被清掉、声明值重新接管。
  于是「声明式给会话档位 + 命令式插播点击回应」可以共存，这也是 `motionReplay` 被删掉的前提。
- `clear()` 改为与参考实现同义：只清命令层（`setOverride(null)`），回落到 `motion` prop，
  没传 prop 才是 `idle`。
- 一次性动作播完后**不再清命令层**，而是让「已完成」的那次下发在下次 `request` 时绕过去重 ——
  同一动作重新下发能重播，同时避免回落层被立刻重播一遍。

### 删除（props 精简）

`PetCommonProps` / `DshPetProps` / `PetProps` 去掉：

- `defaultMotion`：缺省固定 `idle`（`usePetMotion` 内部不再有回落层参数）
- `motionReplay`：命令面能覆盖声明层之后它就没必要了，重播走 `pet.motion({ replay: true })`
- `reducedMotion`：改为自动跟随系统 `prefers-reduced-motion`（`useReducedMotion()` 无参）
- `idleRoll`：空闲掷骰链改为纯配置驱动（`supportsIdleRoll(config)`）
- `petId`：dsh-pet 多开配置固定渲染 `pets[0]`

## 第八轮：`cache` 的存储改走 useIDBKeyval

修上一轮的失误：`cache` prop 该用仓库既有的 `useIDBKeyval`，我却自己写了个直连 `idb-keyval`
的模块，把那两个 hook 一起架空了。现在：

- `utils/media-cache.ts` 只留与 IndexedDB 无关的两件事：`fetchMediaBlob`（抓资源 + 修正 MIME）、
  `createMediaObjectUrl`（blob → object URL 按源去重）。
- `hooks/use-cached-media.ts` 保持原来的形状（`useCachedMediaUrl(source, cache, onError) → string | null`），
  内部读/写全交给 `useIDBKeyval`（`[data, setData, { isFinished }]`），顺带白拿跨标签页同步。
- 两个必须自己兜的点（都写在 hook 注释里）：
  1. **条目带 `source` 标记**：`useIDBKeyval` 换 key 时只重读、不复位 state，读到缺失的 key
     会一直留着上一个 key 的值 —— 不校验标记就会把上一个动画的 blob 当当前动画播；
  2. **一个 source 只解析一次地址**：后台写回 / 迟到的读命中都发生在动画已经在播之后，
     中途换地址会让 `<video>` 从头重播；后到的缓存留给下一次播放。开缓存时先等首次读取
     落地再定地址，避免先按远端地址白加载一次。
- 中途试过把「按源挂载」做成 `MediaSource` 组件，已按反馈删除；实现回到 hook + `useIDBKeyval`。
